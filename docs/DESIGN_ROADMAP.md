# Swjsh Algo Knife - Comprehensive Design & Roadmap

## 1. Design Philosophy & UI/UX
**Core Aesthetic**: "Sleek Dark Mode" / "Cyber-Industrial". 
- **Palette**: Deep Gunmetal backgrounds (`#0f172a`), Electric Cyan (`#06b6d4`) primary, Neon Purple (`#a855f7`) accents.
- **Surface**: Glassmorphism everywhere. Translucent panels with blur (`backdrop-filter: blur(12px)`).
- **Typography**: `Inter` or `JetBrains Mono` for data. Creating a "Terminal" feel but with modern polish.

### Key UI Views
1.  **Command Dashboard (Home)**
    -   **Header**: Global ticker tape (simulated), status indicators, search.
    -   **Main Grid**: Draggable/resizable widgets (using CSS Grid).
    -   **Active Signals Panel**: Live alerts from strategies (ORB 15m).
    -   **Quick Log**: Mini-form to jot down execution notes immediately.

2.  **The "Black Box" (Strategy Center)**
    -   List of strategies (ORB, Supp/Res).
    -   Toggle ON/OFF.
    -   Configuration Inspector: Edit parameters (e.g., "Breakout Threshold: 0.5%") via slider inputs.
    -   Performance chart for each strategy.

3.  **Trader's Ledger (Journal)**
    -   Data Grid: High density, sortable columns.
    -   Detail View: Slide-over panel when clicking a trade. Shows chart snapshot (integrated image), PnL, Entry/Exit/Stop markers.

4.  **Live Feed (The "Pulse")**
    -   Scrolling timeline of market events and system logs.
    -   Visual differentiating between "INFO", "SIGNAL", "EXECUTION".

## 2. Frontend Architecture (Next.js)
-   **Framework**: Next.js 15 (App Router).
-   **Styling**: Vanilla CSS Modules with a global HSL variable system.
    -   Why? Maximum control over performance and "glitch" effects without fighting utility framework overrides.
-   **State Management**: 
    -   `Zustand` for global app state (Sidebar active, User preferences).
    -   `React Context` for Real-time Data Feed (WebSocket connection).
-   **Charts**: `lightweight-charts` (TradingView's open source lib) for fast canvas rendering.

### Component Hierarchy
```
src/
  components/
    layout/         # Sidebar, Header, MobileNav
    dashboard/      # Widgets (SignalCard, PnLChart)
    journal/        # TradeTable, TradeDetailPane
    strategy/       # ConfigForm, BacktestResult
    ui/             # GlassPanel, NeonButton, StatusBadge
```

## 3. Backend Architecture
-   **Runtime**: Next.js API Routes (Serverless/Edge friendly).
-   **Database**: SQLite (`better-sqlite3`) for local MVP. 
    -   *Migration Path*: Postgres (Supabase/Neon) for Cloud V1.
-   **Data Ingestion**:
    -   **Webhooks**: `/api/webhook/tradingview` -> Receives JSON payload from TradingView Alerts.
    -   **WebSocket**: Custom local server (integrated into Next.js dev server or separate Node process) to push updates to frontend.

### Database Schema (ERD Sketch)
-   **Trades**: `id, symbol, direction, entry_price, size, pnl, strategy_ref_id, notes, screenshot_url, created_at`
-   **Strategies**: `id, name, config_json, is_active`
-   **Logs**: `id, severity, message, timestamp`
