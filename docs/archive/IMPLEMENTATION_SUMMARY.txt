EXECUTION MODES COMPARISON
================================================================================

DIRECT ALPACA (NEW) ✨
├─ Path: Bitcoin Bob → AlpacaExecutor → Alpaca REST API
├─ Latency: ~500ms (direct API call)
├─ Order Volume: Market orders only, immediate execution
├─ Position Tracking: In-memory active_trades list
├─ Logging: agent_utils + stdout
├─ Best For: Single-agent paper trading with low latency
├─ User Context: Single account (env vars)
└─ Fallback: If alpaca_executor fails, skips trade

WEBHOOK FALLBACK (Legacy)
├─ Path: Bitcoin Bob → Webhook → Next.js Executor → Alpaca
├─ Latency: ~1000ms (2 HTTP round-trips)
├─ Order Volume: Full executor capabilities (limit, stop, advanced)
├─ Position Tracking: SQLite database
├─ Logging: Database + Discord + Firebase
├─ Best For: Production multi-user trading platform
├─ User Context: Multi-tenant with user isolation
└─ Fallback: Always available if webhook server running

KEY IMPLEMENTATION DETAILS
================================================================================

POSITION SIZING
├─ Risk: 1% of account cash per trade
├─ Formula: qty = ($account * 0.01) / (entry_price - stop_loss)
├─ BTC Example: qty = $1,000 / ($72,800 - $72,000) = 1.25 BTC
└─ Rounding: 4 decimals for crypto, minimum 0.001 BTC

ORDER SUBMISSION
├─ Type: Market orders (immediate execution)
├─ Symbol Format: "BTC/USD" (not "BTCUSD")
├─ Side: "buy" or "sell"
├─ Time in Force: "gtc" (Good til Cancelled for crypto)
└─ No pending delay - fills instantly at market price

EXIT HANDLING
├─ TP Hit: execute_on_alpaca() → close_position()
├─ SL Hit: execute_on_alpaca() → close_position()
├─ Method: DELETE /v2/positions/{symbol}
└─ Liquidates entire position immediately

ERROR HANDLING
├─ Missing credentials: AlpacaExecutor.__init__() raises ValueError
├─ API errors: Caught and logged, trade skipped (graceful degradation)
├─ Network failures: Timeouts = 10s, caught and retried via webhook
├─ Position not found: close_position() returns None (safe)
└─ All errors logged to stdout for monitoring
